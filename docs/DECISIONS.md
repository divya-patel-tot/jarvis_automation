# Phase 0 decisions log (measured on Win10 19045, Python 3.11.9, cursor-sdk 1.3.1, 2026-11-16)

- **D-001 Backend**: SDK is default (bridge start 1.3 s, agent create 0.9 s, warm run ~4 s, cold run with 1 shell call ~20 s). CLI not installed → fallback only.
- **D-002 Windows/3.11 bug**: `cursor_sdk.Bridge.launch` uses `os.get_blocking` + `selectors` on a pipe → crashes on Windows < 3.12. Fixed with our launcher `jarvis/backend/sdk_bridge_win.py` (reader thread, Job Object, no console window).
- **D-003 Plan mode**: `mode="plan"` makes no changes; plan text arrives in a `createPlan` tool call (`args.plan`). **`local.force=False` does NOT prevent writes** in the SDK → not a safety lever.
- **D-004 Cancel**: `run.cancel()` needs a client with env-key fallback; ends stream in ~10 ms. Hard kill via Job Object 0.1 s (5 processes). E2E kill switch 0.39 s.
- **D-005 Rules**: `AGENTS.md` in workspace is honoured with `setting_sources=["project"]`.
- **D-006 Enforcement**: `.cursor/cli.json` deny rules are **ignored** by the SDK. `.cursor/hooks.json` hooks work: `preToolUse` (all tools, `tool_name`+`tool_input`), `beforeShellExecution`, `beforeReadFile`; `{"permission":"deny"}` blocks before execution. One unknown event name disables **all** hooks.
- **D-007 No FS sandbox**: agent file tools can write outside the workspace → enforced by the hook (path policy).
- **D-008 Voice**: Windows dictation langs en-IN/en-US (no hi-IN); voices David/Zira; online-speech privacy toggle OFF and no microphone on this machine at test time.
- **D-009 Isolation**: separate low-privilege Windows user not yet set up → reduced isolation; compensated by hook + plan gate + observer.
- **D-010 Autonomy (user requirement, 2026-11-16)**: default `autonomy=full` - one command runs to completion (incl. installs, settings, real email via `send_mail.py`); only deletions are held by the hook (`NEEDS DELETE CONFIRMATION`) and confirmed once (click or fresh spoken 'confirm'). Always blocked: credential theft, disabling Defender/UAC, boot config, backup/log tampering. After untrusted content: network sends + tier-3 blocked. Routines always run in safe mode. E2E: create = 0 approvals, delete = 1 approval -> Recycle Bin.
- **D-011 STT**: on this PC the offline WinRT wake grammar works ('hey jarvis' conf 0.80) but WinRT free-form recognition (web-search AND dictation topics) returns status=Unknown with empty text even with Online speech recognition ON (unpackaged desktop app). Commands now use local **faster-whisper** (base, int8, CPU; auto en/hi); Windows dictation auto-falls back to Whisper on status=Unknown. Policy state is reset to locked plan/safe after every run (stale execute grant bug found by tests).
- **D-012 Startup deadlock**: secrets.redact() lazily imported keyring INSIDE a logging handler (holding the handler lock) while another thread was importing keyring and logging -> both threads blocked forever, Jarvis froze silently after the banner (proven with py-spy). Fix: key cache primed on the main thread before handlers exist; redact() never imports/does I/O; heavy imports (faster_whisper) on the main thread; Whisper loads with local_files_only (no HuggingFace network check).
- **D-013 Voice v2 (from live logs)**: WinRT wake list rejected one-breath 'hey jarvis <command>'; Whisper auto-language picked Norwegian; Start-menu hotwords caused 'Client Key Manager' x40 hallucinations; follow-up listening heard Jarvis's own TTS. Now: one continuous mic stream, openWakeWord hey_jarvis (score 1.00 on synthesized one-breath commands, ~1.5% CPU idle), 1.5 s pre-roll + VAD capture, Whisper restricted to en/hi with curated hotwords, segment confidence + repetition filters, never listens while speaking, follow-up only after the answer is spoken.
- **D-014 Queue + memory**: agent tasks queue FIFO (max 5, duplicates within 2 min merged: 'Already on it') instead of being rejected; fast-path commands never wait. Every turn is stored in SQLite (%LOCALAPPDATA%/Jarvis/state/history.sqlite3); the last 8 turns + open windows go into each task context so follow-ups ('write X in it') work across sessions and restarts.
- **D-015 Mic stall + speed**: live run showed the capture stream silently stop delivering audio after a task started (py-spy: voice thread blocked on an empty queue, no exception); could not reproduce on demand (mic kept flowing through TTS twice), so a 2 s no-audio watchdog reopens the stream. Added instant close_app (WM_CLOSE) - 0.03 s vs 60 s via agent. Agent prompts inline the context + library table (no exploratory reads); direct actions use the fast model.
